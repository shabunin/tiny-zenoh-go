# Saved topologies

Ready-made containerlab topologies (generated by `../presets.sh` with
`gen.py`; regenerate after changing either). Each directory holds
`topo.clab.yml`, the routers' configs in `cfg/`, `addrs.txt` (the link
addresses `run.sh up` applies) and `lab.env` (names for the scenarios:
`LINK_a_b`, `<HOST>_ARGS`, `<HOST>_AT`, ...). `run.sh` finds them by name,
as it does those in `topos/`.

| preset | what | scenario |
|---|---|---|
| `ring4-mixed` | 4 routers in a ring, tzd and zenohd alternating; c1 on r1, c2 on r3 | `failover` |
| `part4-mixed` | ring of 4 (tzd, tzd, zenohd, zenohd) with replicated memory storages on r1 (tzd) and r3 (zenohd) | `partition` |
| `ring8-storage-mixed` | ring of 8 alternating, storages on r1, r4, r6, gossip on | by hand |
| `gw-mixed` | gateways r1 (tzd) and r2 (zenohd) of a peer cell p1, p2 (Go peers); r3 (tzd) north with client c1; gossip | `gateway` |
| `line3-netem-mixed` | c1 – r1 (tzd) – r2 (zenohd) – r3 (tzd) – c2, 64 KB TCP send buffers | `netem` |
| `grid49-tzd` | 7x7 grid of tzd; hosts h1..h8 (corners, centre, spread) | `scale` |
| `grid100-mixed` | 10x10 grid, tzd and zenohd alternating; hosts h1..h8 | `scale` |
| `rnd60-mixed` | 60 routers on a random connected graph (seed 7, average degree 3), alternating; h3 on the busiest router (r46, 10 links) | `scale` |

All routers use a 2 s lease and no multicast; nodes have no management
network, only the lab links, and do not restart with the host. While a lab
is up, a watchdog kills it if the host runs low on memory (`GUARD_MIB`,
default 2000).

## Running one

On the lab host, in the lab directory (after `./build.sh` here, the rsync
and `sudo ./run.sh image` there):

```bash
sudo ./run.sh up grid100-mixed
sudo ./run.sh scale grid100-mixed        # or leave it up and look around:
sudo ./run.sh down grid100-mixed
```

## Looking around by hand

Every host container (`c1`, `c2`, `h1`.., `p1`..) has `zlab`; `lab.env`
holds the arguments that connect it (`-e` locator, peer mode, ...).

```bash
. presets/grid100-mixed/lab.env
ns() { echo "clab-$LAB-$1"; }

# A subscriber on one corner, a publisher on the other.
docker exec "$(ns h1)" zlab sub $H1_ARGS -k 'demo/**' -d 1h
docker exec "$(ns h2)" zlab pub $H2_ARGS -k demo/x -rate 10 -d 1h

# Liveliness: hold a token and watch everyone's.
docker exec "$(ns h4)" zlab alive $H4_ARGS -k demo/alive/h4 -watch 'demo/alive/**' -d 1h

# Storages (part4-mixed, ring8-storage-mixed): put, then read them back.
docker exec "$(ns c1)" zlab put $C1_ARGS -k lab/store/a -v hello
docker exec "$(ns c2)" zlab get $C2_ARGS -k 'lab/store/**'

# The routers' admin space (tzd and zenohd alike): who they are, their
# sessions, the link-state graph (Graphviz), metrics.
docker exec "$(ns h1)" zlab get $H1_ARGS -k '@/*/router'
docker exec "$(ns h1)" zlab get $H1_ARGS -k '@/*/router/linkstate/**'

# Cut a link (both ends), bring it back.
sudo ip netns exec "$(ns r1)" ip link set eth1 down
sudo ip netns exec "$(ns r1)" ip link set eth1 up
# ... or every link of a router:
for v in $(set | sed -n 's/^\(LINK_[a-z0-9]*_[a-z0-9]*\)=.*/\1/p' | grep -E '^LINK_(r56_|.*_r56$)'); do
	for e in ${!v}; do sudo ip netns exec "$(ns ${e%%:*})" ip link set ${e##*:} down; done
done

# Degrade one: delay, jitter, loss, a bandwidth cap (remove with "del").
sudo ip netns exec "$(ns r1)" tc qdisc replace dev eth1 root netem delay 50ms 10ms loss 2%
sudo ip netns exec "$(ns r1)" tc qdisc del dev eth1 root

# A router's log; a tzd router dumps its goroutines on SIGUSR1 (when it
# seems stuck).
docker logs "$(ns r1)"
docker kill -s USR1 "$(ns r1)" && docker logs "$(ns r1)" 2>&1 | tail -100
# ... and on SIGUSR2 prints its Go memory figures and writes a heap profile.
docker kill -s USR2 "$(ns r1)" && docker logs "$(ns r1)" 2>&1 | grep '^mem:' | tail -1
docker cp "$(ns r1)":/tmp/tzd-heap-1.pprof . && go tool pprof -top tzd-heap-1.pprof

# Memory and CPU of everything.
docker stats --no-stream | grep "clab-$LAB-"

# A picture of the topology (web page on port 50080).
sudo containerlab graph -t presets/grid100-mixed/topo.clab.yml
```

Which link is which: `LINK_r1_r2='r1:eth1 r2:eth1'` in `lab.env` (the
first node dials the second; link k has 10.x.y.0/24, dialer .2, listener
.1, see `addrs.txt`).
